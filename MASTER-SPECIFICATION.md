# YOUTUBE BUDDY X — ULTIMATE MASTER APPLICATION BUILD PROMPT
## Complete UI + UX + AI + Creative Studio + YouTube Intelligence + Cloud Architecture Specification

**Product name:** YouTube Buddy X  
**Product identity:** One Idea. Every Creative Tool. One Intelligent Studio.  
**Main mission:** Build an exceptionally intuitive, beautiful, animated and powerful AI creative super-studio that enables a 5th-grade student to create content easily while giving professional editors, filmmakers, animators, VFX artists, designers and YouTube creators advanced, genuine creative control.

**Primary objective:** Transform my existing YouTube Buddy project into a unified platform for idea generation, prompt engineering, image generation, video generation, storytelling, cinematography, professional editing, generative reframing, animation, 3D, VFX, audio, branding, quality inspection, YouTube channel analysis, monitoring, content strategy and publishing.

**Reference capabilities:** Higgsfield, Adobe Photoshop, Adobe Premiere Pro, Adobe After Effects, DaVinci Resolve, Canva, CapCut, Blender, Runway, Descript, ElevenLabs and YouTube Studio. Use these products as capability references, not as sources of proprietary code or unauthorized assets.

**Non-negotiable rule:** Build real workflows backed by actual software engines, models and integrations. Do not create a beautiful mockup that contains buttons which do nothing.

# SECTION A — HOW YOU MUST APPROACH THE PROJECT

## A1. Your role

Act as a multidisciplinary team containing a principal architect, product designer, motion designer, frontend engineer, backend engineer, AI/ML engineer, media-processing engineer, 3D/VFX engineer, security engineer, cloud engineer and software-testing engineer.

Work inside my existing repository whenever it is available. First inspect the application, understand its architecture and preserve useful working functionality.

Do not assume the project is empty or automatically replace it with a new starter template.

## A2. Start with an actual repository audit

Before making large changes:

1. Inspect all project folders, source files, pages, components and configuration files.
2. Determine the frontend, backend, database, authentication and deployment architecture.
3. Identify existing AI generators, trained models, APIs, agent workflows and processing engines.
4. Inspect how images, videos, audio, user projects and generated assets are stored.
5. Review existing YouTube integration, OAuth flows and analytics logic.
6. Identify unfinished components, mock responses, broken imports, missing dependencies, exposed secrets and failing tests.
7. Run the existing application's available checks and tests.
8. Create a safe baseline or recoverable version before destructive modifications.
9. Create a feature-by-feature gap report against all 30 categories below.
10. Make changes incrementally, retaining existing capabilities that already work.

Use this status system in the project:

- **Planned:** Specified but not implemented.
- **In Development:** Implementation has started.
- **Implemented:** Code exists and the intended operation is connected.
- **Tested:** The relevant functional tests passed.
- **Blocked:** A real dependency, credential, hardware resource or permission is missing.
- **Unavailable:** The capability cannot currently be provided by the selected engine or provider.

Do not mark a feature as completed merely because its UI has been created.

## A3. Fundamental product principles

The platform must be:

- Exceptionally simple for beginners.
- Deep and flexible for expert creators.
- Visually polished and distinctly branded.
- Fast and responsive on ordinary hardware.
- Modular and extensible.
- Secure by default.
- Free-first and open-source-first.
- Under my control wherever technically and legally possible.
- Transparent about AI models, limitations, resource use and costs.
- Built around real creative work rather than generic dashboards.
- Connected across all studios through shared projects and assets.

## A4. Free-first rule

My goal is to use free, open-source and owner-controlled software, models, infrastructure and storage, with the custom domain being a separate expense.

Prefer:

1. Open-source software and models with licenses compatible with the intended use.
2. Self-hosted or owner-controlled inference where suitable resources exist.
3. Model weights and assets stored in my cloud storage where redistribution and hosting are permitted.
4. Genuine free-tier services within their published limits.
5. Optional external paid providers only when explicitly approved.

Never silently purchase credits, enable a paid subscription, create billable cloud resources or call a paid generation endpoint.

**Technical truth:** Free cloud storage does not provide free unlimited GPU computation. Large video models, advanced 3D renders, VFX and long-running inference require appropriate processing resources. Never promise unlimited free generation or hide resource restrictions.

Build a capability and resource registry so the UI can accurately state whether a model is available, whether it runs locally or remotely, what its limits are and whether additional resources are required.

# SECTION B — WORLD-CLASS USER INTERFACE AND USER EXPERIENCE

## B1. Product design goal

Build an interface that feels like a premium creative instrument: modern, cinematic, fluid, polished and approachable.

A beginner should not feel that they have opened professional editing software full of confusing panels. An expert should not feel that they have been locked inside a simplified mobile editor.

Use progressive complexity. Offer Simple, Advanced and Expert controls wherever appropriate.

Do not directly copy the proprietary design of Google, Adobe or any other company. Use excellent usability principles and create an original YouTube Buddy visual identity.

## B2. Visual identity and colors

Use a dark-first creative theme with an optional light theme.

Suggested initial palette:

- Main background: `#080B14`
- Primary panels: `#101625`
- Secondary panels: `#171F32`
- Elevated surfaces: `#202A40`
- Primary brand purple: `#7C3AED`
- Interactive blue: `#4F7CFF`
- Creative cyan: `#22D3EE`
- Main text: `#F8FAFC`
- Secondary text: `#A8B3C7`
- Muted text: `#77839A`
- Success: `#22C55E`
- Warning: `#FBBF24`
- Error: `#F87171`

Use a consistent token system rather than scattered color values.

Purple can identify primary creation actions, blue can identify navigation and selected elements, and cyan can provide subtle creative highlights. Success, warning and error colors should communicate meaningful states.

Do not use neon gradients on every panel, excessive glow, illegible text or decorative motion that interferes with editing.

## B3. Typography and component system

Use a readable modern font such as Inter or Geist.

Create reusable tokens for:

- Font sizes and weights.
- Line heights and letter spacing.
- Spacing.
- Border radii.
- Surface elevations.
- Shadows.
- Focus indicators.
- Icon sizes.
- Button dimensions.
- Input heights.
- Responsive breakpoints.
- Motion durations and easing curves.

Use a consistent icon set such as Lucide. Use real labels alongside unfamiliar icons. Important actions must never depend exclusively on an icon or emoji.

Build reusable buttons, inputs, dropdowns, dialogs, tooltips, tabs, sliders, segmented controls, notifications, progress indicators and confirmation dialogs.

Every control must have usable focus, hover, disabled, loading, success and error states.

## B4. Signature animated home screen

The home screen must immediately answer:

**“What do you want to create today?”**

Include:

- A welcoming greeting.
- A prominent prompt input.
- Upload and drag-and-drop controls.
- Image, Video, Story, Animation, Shorts, Audio, VFX and Design creation choices.
- Quick access to recent projects.
- Recent generations and assets.
- Favorite tools.
- Current render and generation jobs.
- A small, useful summary of connected YouTube activity when a channel is authorized.
- A search field for projects, assets and tools.
- Clear indicators for unavailable models or missing setup.
- A help button and a simple first-time-user guide.

The prompt field should accept normal language. For example:

“Create a cinematic night-time mountain scene with glowing blue energy, dramatic camera movement and a vertical version for Shorts.”

Buddy should identify the intended output and open the appropriate real workflow.

If required information is missing, ask a short, understandable question rather than overwhelming the user with a technical configuration form.

Organize the application around these workspaces:

Avoid exposing every menu item at once to beginners. Use logical groups, expandable sections, tool search and a command palette.

## B6. Animation quality

Implement coherent, restrained motion for:

- Page transitions.
- Navigation.
- Tooltips and menus.
- Panel expansion and collapse.
- Project cards.
- Generation progress.
- Media previews.
- Timeline interactions.
- Canvas pan and zoom.
- Loading skeletons.
- Success and error notifications.
- Modal appearance.
- Workflow-canvas connections.
- Interactive creation cards.

Do not delay user interaction for decorative animation. Respect reduced-motion preferences, keyboard usage and accessibility.

## B7. Universal project workspace

The project workspace should support:

- Project title and type.
- Main preview area.
- Relevant studio tools.
- Asset browser.
- Inspector panel.
- History and versions.
- Job progress.
- Export controls.
- Context-sensitive AI assistance.

Use different layout arrangements for image editing, video timelines, audio, 3D and workflow graphs. Do not force all creative disciplines into the same ineffective layout.

## B8. Device support

Create responsive experiences for desktop, tablet and mobile.

Desktop should expose the most advanced editing tools. Tablets should retain useful touch controls. Mobile should prioritize quick creation, review, uploading, simple edits and project monitoring.

Do not promise that a mobile browser can perform heavy 3D renders or run large local models beyond its capabilities.

## B9. Universal UI states

Every screen needs appropriate states for:

- First-time use.
- Empty projects.
- Loading.
- Uploading.
- Running jobs.
- Completed jobs.
- Failed jobs.
- Cancelled jobs.
- Missing credentials.
- Missing permissions.
- Unsupported formats.
- Quota exhaustion.
- Disconnected integrations.
- Insufficient compute resources.
- No network.
- Recoverable errors.
- Project restoration.

Provide understandable messages and useful next steps. No blank screens, indefinite spinners or fake success.
